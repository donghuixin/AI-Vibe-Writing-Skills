# 论文品鉴评价规程

这是本项目设计的**有证据的定性评价体系**，不是某位研究者的原话、官方审稿量表或经过统计验证的录用预测模型。按论文类型与任务选择维度，不把所有文章套进硬件系统模板。

## 评价顺序

先标明读了什么，再判断核心承诺能否站住，最后分析论证、表达和可迁移价值。评价对象是论文中的具体内容，不是作者人格或声望。

| 层次 | 维度 | 回答的问题 |
|---|---|---|
| 科研内容 | D1 问题价值、D2 贡献定位、D3 关键洞察、D4 证据有效性、D5 边界与诚实性 | 值得解决什么、增加了什么知识、凭什么相信 |
| 论证结构 | D6 挑战到设计、D7 模型到决定、D8 实验到问题、D9 章节交接 | 作者如何把读者带到结论 |
| 表达与阅读 | D10 多尺度概览、D11 句段推理与语气、D12 图表解释 | 能否低成本而不失真地理解 |
| 复用价值 | D13 可复核性、D14 可迁移知识 | 别人能够检验、采用或继续研究什么 |

同一个现象可以影响多个维度，但必须说明不同影响，不重复记成多个独立缺陷。例如预算不公平在 D4 是归因失效，在 D8 是实验无法回答问题；只能算一个根因。

## 等级、置信度与门槛

- `strong`：在声明范围内有明确、可定位的充分依据，并处理关键替代解释或适用边界。
- `adequate`：主要职责完成，存在不改变当前限定结论的局部不足。
- `weak`：已读材料显示重要缺口、矛盾或表达障碍，并能指出为何影响该维度。
- `not_assessable`：材料、专业背景或核验不足；说明缺什么及它会改变哪个判断。
- `not_applicable`：该维度与本文承诺无关；说明原因，不视为失分。

置信度另记 `high / medium / low` 并给理由。`high` 可以仅指“已确认文中如何表述”，不能暗示真实世界结论也已独立验证。没有判断的维度置信度写 `not_assessed`。不能靠词数、引用数、图数或自己生成的概率确定等级。

证据门槛对**具体核心主张**记录：

| 状态 | 含义 | 后续 |
|---|---|---|
| `supported_in_scope` | 已检查的材料在限定范围支持它；不等于独立复现 | 保留条件，分析其优点 |
| `concern` | 已发现反证、归因混杂或关键不一致 | 明确最小可保留结论与需修复点 |
| `unresolved` | 有关键未知，尚不能判断成立或失败 | 标明所缺材料；不宣判错误 |
| `not_checked` | 当前任务未核查该主张 | 不输出全篇有效性结论 |

不将上述状态压成“整篇通过”。存在 `concern` 的论文仍可有值得学习的局部设计；但不能说“整体高分，因此可信”。发现疑似不当行为只描述证据与待核实问题，不从一个异常推断作者动机。

## 维度锚点

### D1 问题价值与场景约束

**看什么**：谁需要什么能力，现状哪一项约束导致损失；任务目标能否转成可观察要求。

- 强：具体使用条件、现有能力缺口与代价相互对应；解释“为什么需要这个问题的解”。
- 充分：需求和对象清楚，但影响范围或约束依据仍可补充。
- 薄弱：只用市场增长、热点或“尚无人做”证明重要性，或设计与真实需求无关。
- 证据位置：问题定义、需求表、先导测量、用户/部署材料；没有用户研究不自动判弱，理论问题也可以由基础知识缺口成立。
- 修复方向：删去不影响目标的宏观背景，补一个决定成功与否的约束。不要替作者捏造用户痛点或成本。

### D2 贡献类型与新颖性定位

**看什么**：相对于同一问题、条件与资源预算下的前作，改变了什么。

- 强：明确新增机制、能力、解释、数据资源或经验，并公平区分已有组件与新组合的必要性。
- 充分：贡献清楚且可查，最近相关工作的差别解释不够集中。
- 薄弱：把实现工作量当创新，把不同任务结果排成优劣，或“首次”没有核验依据。
- 证据位置：贡献段、直接相关工作、对比条件；未核验关键前作时新颖性应为无法判断，而不是直接肯定或否定。
- 修复方向：写清旧方法在什么条件下受限、本文在哪个轴上推进。系统整合并非天然不新颖，新增公式也并非天然更好。

### D3 关键洞察与解释力

**看什么**：论文是否给出非平凡的原因或组织原则，使设计选择变得可理解。

- 强：洞察解释瓶颈，并导出可测试预测或具体设计；一个小例子足以展示与直觉方案的差别。
- 充分：关键想法可以恢复，但被模块清单、术语或长推导遮住。
- 薄弱：只有“结合 A 与 B”“采用先进模型”，无法解释为什么在此条件下有用。
- 证据位置：关键观察、失败案例、简化推导、机制实验。
- 修复方向：询问“去掉这一洞察，设计还能如何被解释”；没有新机制的测量论文也可贡献新的组织规律，不强求算法发明。

### D4 证据有效性与归因

**看什么**：证据是否真正支持所声明的因果、性能或可行性结论。

- 强：对照与预算匹配、独立单位清楚、误差来源被处理；区分实测、推导、模拟、估算与外部报告。
- 充分：限定结论有支持，部分鲁棒性或精度仍不清楚但不被用于更强断言。
- 薄弱：关键比较混杂、数据泄漏、伪重复、选择性报告，或把模拟当实测、相关性当因果。
- 证据位置：方法、实验配置、数据划分、图表注释、统计说明和补充材料。只提供摘要时为无法判断。
- 修复方向：先缩小允许归因，再指出能区分替代解释的最小验证。误差条不自动证明显著性；不统一要求所有研究使用 p 值或随机对照。

### D5 贡献边界、失败条件与诚实性

**看什么**：读者是否知道结论在哪些条件成立，哪些缺口可能影响核心贡献。

- 强：限制具体、影响路径明确，摘要/结论/实验范围一致，并区分已知失败与未测试。
- 充分：关键范围已交代，少数影响分析不足。
- 薄弱：以“未来工程优化”跳过核心验证，或在讨论中承认范围却在结论恢复无条件承诺。
- 证据位置：目标声明、失败结果、讨论、限制及结论。没有独立 Limitations 章节不等于没写边界。
- 修复方向：写清“限制 -> 受影响的主张 -> 仍可保留的结论 -> 还需验证什么”。不能把近距离直接解释成更安全。

### D6 挑战、设计与实现的必要联系

**看什么**：每个重点设计是否解决一个已建立的问题，以及它的输入输出如何衔接。

- 强：瓶颈导出设计，备选方案与取舍可解释；实现细节围绕决定可行性的部分展开。
- 充分：主要对应关系成立，个别关键选择只给结果未给理由。
- 薄弱：Introduction 列的挑战在 Design 消失，或系统只剩器件/网络层清单。
- 证据位置：架构图、设计开头、模块接口、实现约束；无系统设计主张的纯理论/综述文章可不适用。
- 修复方向：补“为什么这里需要该模块”的桥梁，而不是为每个模块虚构一个挑战。多对一和一对多对应都可合理。

### D7 模型、假设到决定的闭合

**看什么**：模型、定理、经验规则或仿真分析究竟改变了哪个判断。

- 强：定义和假设有物理/任务含义，输出进入参数选择、算法、界限或可验证预测；残差得到解释。
- 充分：模型用途明确，部分参数来源或近似条件还不完整。
- 薄弱：公式只作装饰，单位/输入输出断裂，或理论保证越过假设用于整个实现。
- 证据位置：模型前的目的、变量定义、推导后的含义、实际参数；纯经验描述无模型承诺时可不适用。
- 修复方向：指出模型的消费者及用法；不能为了像理论论文而增加没有证据的公式。理论论文的“决定”可以是定理解释，不强求硬件参数。

### D8 实验问题与证据组织

**看什么**：每组实验/分析回答什么，为什么按此顺序出现。

- 强：总体有效性、机制解释、敏感性、代价和边界各有职责，覆盖所宣称的贡献而不堆数量。
- 充分：核心问题有对应结果，但局部图表主旨或实验之间的联系不明确。
- 薄弱：实验很多却不回答主张；只展示成功案例，或用总体性能替代机制归因。
- 证据位置：评估开头的问题、图前设问、图后解释、条件扫描；理论论文可对应定理/反例/实例，不强制消融。
- 修复方向：给每张关键图写一句“它排除了什么疑问”。D8 看组织和覆盖；D4 看这些证据本身是否有效。

### D9 篇章结构与信息交接

**看什么**：每节接住前文什么问题，产出后文需要的什么信息。

- 强：背景只引入必要概念，核心概念在使用前足够定义，章节分工明确，承诺与证据闭环。
- 充分：结构可跟随，存在少量可压缩的重复或回溯。
- 薄弱：按开发日志叙述，关键前提藏得太晚，或多节反复宣告同一结论而不推进。
- 证据位置：标题、节首/节尾、跨节引用、论证路线图。
- 修复方向：按读者依赖关系排序。Related Work 在前或在后、实验与设计交织都可以成立，不能按固定目录判优劣。

### D10 标题、摘要与引言的多尺度概览

**看什么**：不同阅读深度是否都能取得准确而相容的主要信息。

- 强：标题体现对象或关键贡献；摘要给出问题、做法与有条件结果；引言建立可信承诺并说明差别。
- 充分：信息准确，但重点不够鲜明或核心洞察出现较晚。
- 薄弱：标题营销化、摘要像目录、引言大篇幅讲行业背景，或概览与正文的范围不一致。
- 证据位置：标题、摘要、贡献段及对应正文。只有摘要也可局部评价表达，但不能据其宣布科研结论成立。
- 修复方向：调整信息优先级，不规定几句、几个词或必须情境故事开头；适用的投稿长度另查官方规则。

### D11 句段推理、术语与作者语气

**看什么**：句子之间的关系真实成立，动作执行者和限定条件稳定，语言是否增加理解成本。

- 强：段落有明确作用，观察到解释再到结论的过渡有依据；术语稳定，叙述克制且保有作者声音。
- 充分：语义正确，偶有冗余或指代不清但可局部修复。
- 薄弱：连接词掩盖推理跳跃、抽象名词遮住动作、量词/条件悄然升级，或用形容词替代技术解释。
- 证据位置：具体相邻句段；必要时组合 17。非母语痕迹、被动语态、长句或术语重复本身不是缺陷。
- 修复方向：先修关系和范围，再修句式。有效原句可明确“保留”，不要把参考文风覆盖到当前作者。

### D12 图表作为解释与证据

**看什么**：图表是否承担正文难以高效完成的解释/比较任务，而非仅视觉装饰。

- 强：示意与实测分开，坐标/单位/样本/条件可辨，图注说明结论范围，正文准确解释趋势与异常。
- 充分：主要信息可读，局部标签、比较口径或误差说明不完整。
- 薄弱：截断坐标或混合尺度误导结论，示意图伪装数据，漂亮热图没有变量/参考含义。
- 证据位置：原始渲染页而不只是 OCR 文本。没有看过原页时视觉质量为无法判断；不因没有图而罚纯证明文章。
- 修复方向：说明图要回答的问题，再改编码、图注或正文；先查数据而不是先美化。

### D13 可复核性与实施透明度

**看什么**：别人能否知道结果如何产生、如何检查，以及没有公开哪些内容。

- 强：版本、数据来源、关键配置、预处理、实现/估算分界与复核入口清楚；受限资料有合理边界说明。
- 充分：主要方法可理解，部分依赖、参数或复现步骤待补。
- 薄弱：核心计算或证据来源无法恢复，链接存在却内容不对应，或以开源声明代替可运行性验证。
- 证据位置：方法、附录、资源页、代码/数据说明。资源未访问应标“未查”，不是断言不可复现。
- 修复方向：列出恢复关键结果最少还缺什么。代码公开、代码运行、独立复现是三个状态；隐私/许可限制不自动等于质量差。

### D14 可迁移知识与后续启发

**看什么**：离开这套具体器件、数据和实现，读者带走什么可验证的理解。

- 强：把成功/失败提炼成带前提的设计原则、界限或可检验假设，说明在哪些新问题上可能有用。
- 充分：有具体经验，但适用条件或下一步验证不明确。
- 薄弱：只说“未来可用于更多场景”，或把偶然的配置收益宣传为通用法则。
- 证据位置：讨论、机制解释、失败分析与复用案例。没有长篇 Future Work 不自动判弱。
- 修复方向：写迁移卡，区分可复用论证动作与不可搬运的研究事实。提出的未来实验不是当前论文已完成的证据。

## 贡献类型适配

| 主要类型 | 更关键的证据 | 不应强制要求 |
|---|---|---|
| 新机制/算法 | 比较公平性、机制预测、复杂度、关键组件作用 | 所有问题都需要现场部署 |
| 系统/平台 | 接口与取舍、端到端能力、瓶颈、成本、使能的新研究 | 每个组件都全新或所有算法都最优 |
| 测量/经验 | 抽样框架、测量工具误差、代表性、混杂、经验边界 | 发明新算法、统一硬件消融 |
| 理论/分析 | 定义、假设、证明、紧致性或反例、适用解释 | 真实原型、用户研究、固定统计检验 |
| 数据集/基准 | 数据来源、许可、覆盖、标注可靠性、划分泄漏、任务意义 | 仅靠作者方法跑赢就证明数据价值 |
| 交互/应用探索 | 任务定义、使用情境、评价协议、参与者范围、定量与定性证据 | 用满意度替代技术准确性或临床有效性 |

多类型论文可组合重点，但评价的是作者承担的承诺，不追求所有维度齐全。新领域需要背景补读时明确自己的判断限度。

## 多论文比较与可选数值

先对齐论文版本、贡献类型、目标约束、已读范围和同一套锚点。先分别评价，再解释差异；可选择不同优点并存，不强行选赢家。年份不同的结果可以比较论证做法，不自动拿今天的硬件和规则否定历史贡献。

只有用户明确要求单项分数时，允许将 `weak / adequate / strong` 映射为 `1 / 2 / 3`，同时保留标签、证据和置信度。`not_assessable / not_applicable` 为 `null`，不得当成零分，也不得填补后计算均分。该序数尺度不表示相邻等级等距，默认不合成总分；用户要求排名时优先给条件化比较及无法比较的理由，不伪造精确胜率。

## 评价完成检查

- 每个已判断维度都能找到来源位置与具体理由吗？
- 优点是否说明了作用，而不只是形容词？
- 未读、未查、提取失败是否与论文真的缺失分开？
- 核心反证是否单列，没有被表达优势抵消？
- 是否至少考虑过一种替代解释或不适用条件？
- 是否保留了有效写法，没有强迫一种目录和文风？
- 迁移建议是否符合当前稿件事实、范围和作者授权？
