## Requirement Coverage
| Item / sub-ask | Exact qualifier or alternative | Classification | Existing answer location | Existing evidence | Minimum sufficient response | New answer location / status |

Classification: explicit_request / optional_path_or_suggestion / internal_check / optional_enhancement.
Status: resolved / partly_resolved / pending / context_only.
Retain whether, either/or, negation and feasibility conditions. Include a reason when selecting an alternative or declining a suggestion. Do not create new reviewer demands from internal checks.

## Evidence And Completion
| Existing claim / evidence ID or source locator | Support state | Result type | Supported scope | Work actually completed | Specific missing item |
| :--- | :--- | :--- | :--- | :--- | :--- |

Reference the existing C/E IDs and source records when the project has a systems-paper worksheet; do not duplicate its facts here. Otherwise use a source, version and location.
Support state: supported / partial / missing / contradicted.
Result type: observed / derived / model_estimated / assumed / proposed / pending. Completion describes work actually done, independently of its evidential support.
Record metric definitions, units, independent sample units and uncertainty methods when relevant. A missing value is not zero. Existing plots may already answer part of a request; inspect them before asking for new experiments.

## Author Response Blocks
For each item, include:
- Original comment, unchanged.
- Author response: direct answer, then only the explanation and evidence needed.
- Completed manuscript change and verified location, if any.
- Short visible pending marker for unresolved essentials.

These are content roles, not compulsory paragraphs. A wording correction may need one sentence; a technical answer may need a compact table. Keep internal audit language and planning outside the authored response.
