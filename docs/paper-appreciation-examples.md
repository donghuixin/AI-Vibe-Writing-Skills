# 论文品鉴合成示例

以下材料全部独立合成，没有取自某位研究者的论文，不含真实测量结论。示例展示判断方法，不是要求 Agent 模仿固定答案。完整等级见 [评价规程](../.ai_context/references/paper_appreciation_rubric.md)。

## 示例一：表达清楚，核心归因仍有缺口

### 输入材料

论文片段 S1 的摘要写：“我们提出一种低开销调度机制，在近距交互中提高传输速率。”引言 P2 明确交互需要低延迟；设计 §3 用队列示例解释调度。表 1 报告新方案速率翻倍，但新方案也使用双倍带宽。§4 没有同带宽对照，结论却把全部增益归于调度。用户只要求品鉴这四处。

### 合适的评价

**Reading Scope**：仅查看上述片段。未读全文、未检查原始数据，不评价全篇新颖性或复现状态。

**优点**：引言 P2 给出的交互约束说明为什么关心延迟；§3 的队列例子把抽象机制变成可跟随的动作。这两点有助于理解设计，但不证明性能增益来自调度。

| 维度 | 判断 | 依据及范围 | 置信度及理由 |
|---|---|---|---|
| D1 问题价值 | adequate | P2 有具体任务要求，但未提供需求阈值的来源 | medium：只评价已交代的任务，不代替需求核验 |
| D3 关键洞察 | not_assessable | 有队列解释的描述，但没有提供具体机制和新观察 | not_assessed |
| D4 证据有效性 | weak | 表 1 同时改变机制和带宽，无法隔离机制收益 | high：混杂直接见于所给比较条件 |
| D5 贡献边界 | weak | 结论的归因超过目前对照支持范围 | high：限定于所给归因主张 |
| D9 章节交接 | weak | P2 的低延迟目标尚未由所给速率结果回答 | medium：未提供部分可能另有延迟证据 |
| D10 多尺度概览 | adequate，仅摘要 | 摘要交代对象与目标；局部清晰不等于全文概览一致 | medium：仅依据这句摘要 |
| D12 图表解释 | not_assessable，仅视觉 | 可以分析表内数字，不能判断未见原图的视觉质量 | not_assessed |
| D13 可复核性 | not_assessable | 未访问配置、数据或代码 | not_assessed |

核心归因记 `concern`，而不是“整体优秀可以忽略”。当前可保留的结论仅是两种配置下结果不同；不能说新机制无效，也不能说其效果已被独立证实。

**迁移卡**：可以学“用小例子解释调度”，前提是例子确实反映算法；不能学“把配置收益全部写成机制收益”。最有价值的下一步是核对同预算比较或收窄归因，不是增加形容词。

## 示例二：理论论文不应被硬件清单误判

### 输入材料

材料 S2 给出一种误差上界。§2 定义输入分布和有界噪声，§3 给出证明，§4 用反例解释放宽假设后为何不成立。用户只提供这三节，没有实验、开源链接或完整相关工作。

### 合适的评价

可以评价定义、证明链的可跟随性和反例的解释作用；没有完成逐步证明核验时，正确性标待核实。D6 的系统实现对应可为 `not_applicable`，D8 可评价“论证问题由定理与反例回答”，不是自动因为缺实验判弱。D2 实质新颖性和 D13 全部复核材料状态保持未知。

**值得学习**：把条件失效的反例紧接定理，帮助读者知道结论边界。**不能照搬**：为了让系统稿像理论稿，补一个没有设计用途的定理。不同类型的知识贡献有不同证据契约。

## 示例三：端到端不是几个数字相加就成立

### 输入材料

材料 S3 实测采集前端功耗，用仿真预测计算模块功耗，通信开销未计入。摘要称“端到端功耗已实测降低”；正文却把两种来源混列在一栏。用户喜欢它“软硬件协同”的叙述。

### 合适的评价

可以肯定把问题分解到感知和计算两端，避免只优化局部瓶颈的论证动作。但 D4 和 D5 对“端到端已实测”存在 `concern`：估算与实测不同，系统边界也不完整。

一张改进后的证据表应分列组件、工作条件、数据来源和未计入项。基于所给材料，最多可改成“我们分别实测采集前端功耗、仿真计算模块功耗；通信开销尚未计入”。是否降低、降低多少仍需要基线与结果，不能补造。不是简单把“实测”换成“证明”就解决问题。

## 示例四：不改也是品鉴结果

### 输入材料

> We estimate the delay from the received signal. The estimated delay determines the sampling window. A shorter window reduces computation but excludes late arrivals.

用户要求欣赏句间关系，不要求改写。

### 合适的评价

第一句的输出成为第二句的输入，第三句解释该决定的代价，读者能跟随“估计 -> 使用 -> 权衡”。`delay` 和 `window` 的重复帮助追踪对象，`A` 开头也没有问题。D11 对这三句可判 `strong`，范围只限局部信息关系；技术内容是否真实仍需方法与数据支持。保留原句，不生成同义替换版。

## 示例五：匿名与归属同时保留

### 输入材料

用户提供有作者姓名、机构、DOI、项目域名和图像元数据的 PDF，要求生成匿名课堂品鉴讲义，不要求公开源论文或私有笔记。

### 合适的处理

匿名讲义使用中性材料 ID，不放可反查的系统名、链接、独特引文、精确成果数字、作者首字母或原图。需要例子时重新构造并标注合成，不能仅将姓名涂黑。原始归属可以在授权的私有记录中保留；是否存储由任务授权决定。不能把临时私有映射写进公开仓库、提交说明或测试报告。

匿名化降低直接识别线索，但不承诺绝对无法重识别。实际论文引用仍需遵守学术归属规则。

## 示例六：公平比较写法，不比较名气

两份材料的技术段落完全相同，仅作者单位和获奖标签不同。D1-D14 的证据判断不应因此改变；身份可以用于检索确认版本，不能给质量加分。若一份有全文、另一份只有摘要，也不应将后者的未知项记零后排名。

比较报告可以说“在已读部分，甲的图注交代条件更完整；乙的模型直觉更易跟随”，同时说明两者任务和阅读覆盖的差异。不能从版式精致、英语地道或顶会标签推出科学可靠性。
